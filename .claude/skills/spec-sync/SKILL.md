# 仕様書同期スキル (spec-sync)

## 目的

機能追加、リファクタ、またはドキュメント構造の変更後に生じる、プロジェクトの主要ドキュメント（`GEMINI.md`, `README.md` 等）と実コード・ディレクトリ構造の乖離を検出し、整合性を維持した状態に同期・更新します。

---

## 最終更新日（Last Updated）の記載ルール

更新を行った際は、ドキュメントに最終更新日を明記または更新し、いつ時点の仕様であるかを誰でも判断できるようにします。

| ドキュメント | 最終更新日の記載方法 | 記載・更新場所 |
|---|---|---|
| `GEMINI.md` | `Updated YYYY-MM-DD`（またはそれに類する表記） | ファイル冒頭付近 |
| `README.md` | `最終更新日: YYYY-MM-DD`（またはそれに類する表記） | ファイル冒頭付近（見出しの直下） |

---

## 対象仕様書・進捗ドキュメントと更新トリガー

| ファイル | 役割 | 更新が必要な変更 |
|---|---|---|
| `GEMINI.md` | エージェント向け仕様（開発の絶対ルール、構成、注意事項） | 設計原則の変更、ルール追加、主要構成の変更 |
| `README.md` | ユーザー向け概要・開発方法・コマンド一覧 | ドキュメント追加、新スクリプトの追加、使い方変更 |
| `package.json` | プロジェクト設定・依存関係・スクリプト定義 | スクリプト定義の追加・削除、依存関係のアップデート |

---

## 監査・確認プロセス

仕様書の整合性を確認する際、またはタスク完了時には、以下の手順を実行し、すべての不整合を解消してください。

### 1. 監査チェックリスト

- [ ] **`GEMINI.md` 監査**
  - [ ] `GEMINI.md` に記載されているルールやディレクトリ構成が、現在のリポジトリ構成と一致しているか。
  - [ ] 最終更新日のタイムスタンプが最新化されているか。
- [ ] **`README.md` 監査**
  - [ ] ドキュメント一覧やスクリプトコマンド一覧が、実際に存在するファイル・`package.json` のスクリプトと一致しているか。
  - [ ] 最終更新日のタイムスタンプが最新化されているか。
- [ ] **`package.json` 監査**
  - [ ] 不要な依存関係や無効なスクリプトが含まれていないか。
  - [ ] 新しく作成した TypeScript スクリプトが登録されているか。

---

## 修正とコミット規約

監査の結果、乖離が検出された場合は直ちに修正し、適切なコミットメッセージでコミットしてください。

### コミットメッセージの例

```bash
git add GEMINI.md README.md package.json
git commit -m "chore(docs): sync spec files with recent changes"
```
