# 開発ガイドライン: TypeScript の使用ルール

本プロジェクトにおけるスクリプトおよびツールの開発において、コードの品質と堅牢性を担保するため、TypeScript の使用をルール化します。

---

## 📌 基本原則

1. **JavaScript（.js）の使用禁止**
   - プロジェクト内のスクリプト、検証ツール、補助プログラムを作成する際は、JavaScript ではなく **TypeScript（.ts）** を使用しなければなりません。
   - 既存の `.js` スクリプトは順次 TypeScript への移行を行います。

2. **TypeScript 最新バージョンの使用**
   - 開発環境およびエディタの Linter/LSP 機能の恩恵を最大化するため、TypeScript の最新安定バージョン（プロジェクト指定: `^6.0.3`）を維持・使用してください。
   - 型定義パッケージ（例: `@types/node`）も最新バージョン（プロジェクト指定: `^25.9.1`）を使用し、型の不整合を防ぎます。

---

## 💡 なぜ TypeScript を採用するのか？

- **型安全性 (Type Safety)**: 引数の誤りやプロパティのタイポなど、実行前に検出可能なバグを事前に防ぎます。
- **エディタ支援 (LSP)**: VS Code 等のモダンエディタにおける強力な補完、シグネチャ確認、リファクタリング支援が受けられます。
- **仕様の自己文書化**: 関数の入力と出力の型が明確になるため、スクリプトの仕様がコード自体で表現されます。

---

## ⚡ Bun を使用した実行環境

本プロジェクトではランタイムとして **Bun** を採用しています。Bun を使用することで、TypeScript 固有の面倒なコンパイル手順が不要になります。

### TS ファイルの直接実行

以下のコマンドで、トランスパイルすることなく TypeScript ファイルを直接実行できます。

```bash
bun ./scripts/verify-links.ts
```

### package.json での定義例

スクリプトを定義する場合は、以下のように直接 `.ts` ファイルを指定します。

```json
"scripts": {
  "check-links": "bun ./scripts/verify-links.ts"
}
```

## 🛠️ スクリプト開発ガイドライン

1. **型定義を明確にする**
   - コールバック関数の引数、APIレスポンスのスキーマ、重要なオブジェクト構造には、インターフェース（`interface`）や型（`type`）を付与してください。
2. **`any` の使用は極力避ける**
   - どうしても型定義のない外部ライブラリを使用するなどの場合を除き、明示的に型を指定してください。
   - 型定義が存在しないライブラリは、必要に応じて `// @ts-ignore` を使用するか、型定義を限定的に作成して回避してください。
