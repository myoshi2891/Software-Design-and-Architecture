Chapter 3

CSSカスタムプロパティ（変数）システム

3.1

カスタムプロパティとは何か

CSSカスタムプロパティ（CSS変数）は、CSS内で定義・再利用できる値の入れ物です。-- で始まる名前で定義し、var() 関数で参照します。

💡
なぜ必要か？
同じ色やサイズを何度も書くと、変更時に全箇所を修正する必要があります。CSS変数を使えば1箇所を変えるだけで全体に反映されます。

定義と参照の基本構文

CSS
/* ── 定義：:root に書くとページ全体で使える ── */
:root {
  --color-primary: #6C47FF;   /* ブランドカラー */
  --space-4:       16px;      /* スペース */
  --font-size-lg:  1.125rem;  /* フォントサイズ */
}

/* ── 参照：var() で呼び出す ── */
.button {
  background:  var(--color-primary);
  padding:     var(--space-4);
  font-size:   var(--font-size-lg);
}

/* ── フォールバック値（第2引数）── */
/* --color-brand が未定義のとき #6C47FF を使用 */
.button {
  background: var(--color-brand, #6C47FF);

  /* フォールバックに別の変数も可能 */
  color: var(--text-on-brand, var(--color-white, #ffffff));
}

3.2

定義・参照・スコープ

CSS変数はDOMツリーの階層構造に従って継承されます。子要素は親の変数を参照でき、より近い祖先で定義された値が優先されます。

図を読み込み中...

▲ 変数のスコープはDOMツリーに従う。section内でローカル上書きすると子のみ影響を受ける

スコープを意識した実装例

CSS
/* グローバルスコープ ── ページ全体で有効 */
:root {
  --color-primary: #6C47FF;
}

/* ローカルスコープ ── .card 内だけ有効 */
.card {
  --card-bg: #1e1e2e;
  background: var(--card-bg);
}

/* .section 内だけ --color-primary を赤に上書き */
.section--alert {
  --color-primary: #ef4444;
  /* この中の子要素は赤を参照する */
}

/* .dark-theme 内でまとめてテーマを上書き */
.dark-theme {
  --color-primary: #9070ff;   /* 暗い背景に合わせて明るく */
  --card-bg:       #2d1e3d;
}
✅
ポイント：グローバルな値は :root に、コンポーネント固有の値はそのコンポーネントのセレクタに定義することで、スコープが明確になります。
3.3

トークンの階層設計

プロダクション品質のシステムでは、デザイントークンを3つの層（プリミティブ→セマンティック→コンポーネント）に分けて管理します。

図を読み込み中...

▲ 3層トークン設計：生の値→意味→コンポーネント固有、と抽象化レベルが上がる

第1層：プリミティブトークン（生の値）

CSS — primitives.css
:root {
  /* カラースケール（色の名前 + 濃淡番号） */
  --purple-50:  #f5f3ff;
  --purple-100: #ede9fe;
  --purple-500: #6C47FF;  /* ← ベースカラー */
  --purple-600: #5a38e0;
  --purple-900: #1e0a5c;

  --gray-50:  #fafafa;
  --gray-100: #f4f4f5;
  --gray-500: #71717a;
  --gray-900: #18181b;

  --red-500:   #ef4444;
  --green-500: #22c55e;
  --amber-500: #f59e0b;

  /* 基本スペース値（4px刻み） */
  --size-1:  4px;   --size-2:  8px;
  --size-3:  12px;  --size-4:  16px;
  --size-6:  24px;  --size-8:  32px;
  --size-12: 48px;  --size-16: 64px;
}

第2層：セマンティックトークン（意味を持つ名前）

CSS — semantic.css
:root {
  /* 「何色か」ではなく「何のための色か」で命名 */
  --color-action-primary:        var(--purple-500);
  --color-action-primary-hover:  var(--purple-600);
  --color-action-primary-subtle: var(--purple-50);

  --color-feedback-danger:   var(--red-500);
  --color-feedback-success:  var(--green-500);
  --color-feedback-warning:  var(--amber-500);

  --color-bg-base:           var(--gray-50);
  --color-bg-surface:        var(--white);
  --color-text-primary:      var(--gray-900);
  --color-text-muted:        var(--gray-500);

  /* スペーシングも意味付け */
  --spacing-xs:  var(--size-1);   /* 4px  */
  --spacing-sm:  var(--size-2);   /* 8px  */
  --spacing-md:  var(--size-4);   /* 16px */
  --spacing-lg:  var(--size-6);   /* 24px */
  --spacing-xl:  var(--size-8);   /* 32px */
}

第3層：コンポーネントトークン（コンポーネント専用）

CSS — components/button.css
:root {
  /* セマンティックトークンをコンポーネント名で包む */
  --button-bg:         var(--color-action-primary);
  --button-bg-hover:   var(--color-action-primary-hover);
  --button-padding-x:  var(--spacing-md);
  --button-padding-y:  var(--spacing-sm);

  --card-bg:           var(--color-bg-surface);
  --card-padding:      var(--spacing-lg);
  --card-border:       var(--color-border-default);
}

/* コンポーネント実装は第3層を参照 */
.button {
  background:  var(--button-bg);
  padding:     var(--button-padding-y) var(--button-padding-x);
}
.button:hover {
  background: var(--button-bg-hover);
}
ℹ️
なぜ3層構造なのか：デザイントークンを3層に分けることで、将来的にプリミティブ（生の色）を変えても、セマンティック・コンポーネント層は変更不要。変更の影響を最小限に抑えられます。
3.4

JavaScriptとの連携

CSS変数の最大の強みはJavaScriptからリアルタイムに読み書きできることです。テーマ切り替えやアニメーション制御に活用できます。

基本的な読み書き

JavaScript
const root = document.documentElement; // = :root 要素

// ── 読み取り ──
const primary = getComputedStyle(root)
  .getPropertyValue('--color-action-primary')
  .trim();
// => "#6C47FF"

// ── 書き込み（リアルタイムに変更）──
root.style.setProperty('--color-action-primary', '#ff6b6b');
// 即座にページ全体の --color-action-primary が更新される

// ── 削除（:root の宣言に戻る）──
root.style.removeProperty('--color-action-primary');

テーマ切り替え実装例

JavaScript
// テーマ定義オブジェクト
const THEMES = {
  light: {
    '--color-bg-base':      '#fafafa',
    '--color-bg-surface':   '#ffffff',
    '--color-text-primary': '#18181b',
    '--color-text-muted':   '#71717a',
    '--color-border':       '#e4e4e7',
  },
  dark: {
    '--color-bg-base':      '#09090b',
    '--color-bg-surface':   '#18181b',
    '--color-text-primary': '#fafafa',
    '--color-text-muted':   '#a1a1aa',
    '--color-border':       '#27272a',
  }
};

function applyTheme(theme) {
  const root = document.documentElement;

  // 全トークンを一括更新
  Object.entries(THEMES[theme]).forEach(([key, value]) => {
    root.style.setProperty(key, value);
  });

  // 設定を永続化
  localStorage.setItem('preferred-theme', theme);
}

// ── 初期化：保存済みテーマ or OS設定 ──
const saved = localStorage.getItem('preferred-theme');
const osDark = window.matchMedia('(prefers-color-scheme: dark)').matches;
applyTheme(saved ?? (osDark ? 'dark' : 'light'));
3.5

CSSカスタムプロパティ — ベストプラクティス

CSS変数を長期的に保守しやすくするための重要なルールを解説します。

✅ 命名は「カテゴリ-役割-修飾子」で統一する

❌ NG — 意味不明な名前
/* 何を表しているか全くわからない */
--c1: #6C47FF;
--blue: #3b82f6;
--big: 24px;
--p: 16px;
✅ OK — カテゴリ-役割-修飾子
/* 一目で役割がわかる命名 */
--color-action-primary:       #6C47FF;
--color-action-primary-hover: #5a38e0;
--color-feedback-danger:      #ef4444;
--font-size-heading-lg:       1.5rem;
--spacing-component-gap:      16px;

✅ @property で型定義する（アニメーション対応）

🧪
CSS Houdini（@property）：型を宣言することで、CSS変数をアニメーション対象にできます。Chrome 85+、Safari 16.4+、Firefox 128+ で対応。
CSS
/* @property で型・初期値・継承を宣言 */
@property --progress {
  syntax:        '<number>';  /* 数値型 */
  inherits:      false;
  initial-value: 0;
}

/* アニメーション可能なプログレスバー */
.progress-bar {
  --progress: 0;
  width: calc(var(--progress) * 1%);
  transition: --progress 0.4s cubic-bezier(0.4, 0, 0.2, 1);
}

/* JavaScript から数値を渡すだけ */
/* el.style.setProperty('--progress', 75); */

✅ デザイントークンファイルを独立させて管理する

File Structure
/* ── 推奨ファイル構造 ──

  tokens/
  ├── primitives.css    ← プリミティブトークン（生の値）
  ├── semantic.css      ← セマンティックトークン（意味）
  └── themes/
      ├── light.css     ← ライトテーマ
      └── dark.css      ← ダークテーマ

  components/
  ├── button.css        ← コンポーネントトークン + スタイル
  └── card.css

トークンファイルは定期的に棚卸しし、
未使用変数を削除することで肥大化を防ぐ */
Chapter 4

カラーシステム

4.1

カラーシステムの目的

カラーシステムとは、プロダクト全体で一貫した色の使い方を保証する仕組みです。「なんとなく合う色」を選ぶのではなく、目的・意味・アクセシビリティに基づいて色を定義します。

図を読み込み中...

▲ カラーシステムが達成すべき4つの目標

🎯
カラーシステムがないと起こること：デザイナーとエンジニアが別の青を使う、ダークモード対応が困難、コントラスト不足でアクセシビリティ違反、変更時に修正箇所が散在する。
4.2

カラーパレットの構造

各カラーを50〜900の10段階スケールで定義します。数値が大きいほど暗くなり、システム全体で一貫した濃淡を使えます。

図を読み込み中...

▲ パープルスケール 50〜900。50が最も淡く、900が最も濃い

パープルスケールの実装例

CSS
:root {
  --purple-50:  #f5f3ff;  /* 最も淡い。背景・ホバー用 */
  --purple-100: #ede9fe;
  --purple-200: #ddd6fe;
  --purple-300: #c4b5fd;
  --purple-400: #a78bfa;
  --purple-500: #8b5cf6;  /* ベースカラー。メインUI用 */
  --purple-600: #7c3aed;  /* ホバー状態 */
  --purple-700: #6d28d9;
  --purple-800: #5b21b6;
  --purple-900: #4c1d95;  /* 最も濃い。ダークテキスト用 */
}

カラーカテゴリの分類

カテゴリ用途代表例
Brandブランドの主色・アクセント--purple-500
Neutral背景・テキスト・ボーダー--gray-100〜900
SemanticUI状態を表す色danger / success / warning / info
Overlayモーダル背景・影rgba(0,0,0,0.5)
4.3

セマンティックカラートークン

「何色か（What）」ではなく「何のための色か（Why）」で命名します。セマンティックトークンがあれば、テーマ切り替え時にプリミティブの参照先を変えるだけです。

図を読み込み中...

▲ プリミティブ層（What）→ セマンティック層（Why）への変換

セマンティックカラートークン完全定義例

CSS — semantic-colors.css
:root {
  /* ── アクション系 ──  */
  --color-action-primary:          var(--purple-500);
  --color-action-primary-hover:    var(--purple-600);
  --color-action-primary-active:   var(--purple-700);
  --color-action-primary-subtle:   var(--purple-50);

  /* ── フィードバック系 ── */
  --color-feedback-danger:         var(--red-500);
  --color-feedback-danger-subtle:  var(--red-50);
  --color-feedback-success:        var(--green-500);
  --color-feedback-success-subtle: var(--green-50);
  --color-feedback-warning:        var(--amber-500);
  --color-feedback-warning-subtle: var(--amber-50);
  --color-feedback-info:           var(--blue-500);
  --color-feedback-info-subtle:    var(--blue-50);

  /* ── 背景系 ── */
  --color-bg-base:       var(--gray-50);   /* ページ背景 */
  --color-bg-surface:    var(--white);     /* カード・パネル */
  --color-bg-overlay:    var(--gray-100);  /* ドロップダウン等 */

  /* ── テキスト系 ── */
  --color-text-primary:  var(--gray-900);  /* メインテキスト */
  --color-text-secondary:var(--gray-600);  /* 補助テキスト */
  --color-text-muted:    var(--gray-400);  /* ヒント・プレースホルダー */
  --color-text-on-primary: var(--white);  /* プライマリ背景上のテキスト */
  --color-text-disabled: var(--gray-300); /* 無効状態 */

  /* ── ボーダー系 ── */
  --color-border-default: var(--gray-200);
  --color-border-strong:  var(--gray-400);
  --color-border-focus:   var(--purple-500); /* フォーカスリング */
}
4.4

ダークモード対応

CSS変数を使えば、ダークモードの切り替えはセマンティックトークンの値を置き換えるだけです。コンポーネントのコードは一切変更不要です。

図を読み込み中...

▲ ライト・ダーク両方から同じコンポーネント変数を参照するアーキテクチャ

2つのダークモード実装パターン

CSS
/* ━━ パターン1: OSのダークモード設定に自動追従 ━━ */
:root {
  --color-bg-base:        #fafafa;
  --color-bg-surface:     #ffffff;
  --color-text-primary:   #18181b;
  --color-text-muted:     #71717a;
  --color-border-default: #e4e4e7;
}

@media (prefers-color-scheme: dark) {
  :root {
    --color-bg-base:        #09090b;
    --color-bg-surface:     #18181b;
    --color-text-primary:   #fafafa;
    --color-text-muted:     #a1a1aa;
    --color-border-default: #27272a;
  }
}

/* ━━ パターン2: ボタンで手動切り替え ━━ */
/* data-theme="dark" を html 要素に付与 */
[data-theme="dark"] {
  --color-bg-base:        #09090b;
  --color-bg-surface:     #18181b;
  --color-text-primary:   #fafafa;
  --color-text-muted:     #a1a1aa;
  --color-border-default: #27272a;
}

/* ━━ コンポーネントはセマンティックトークンを使うだけ ━━ */
/* テーマが変わっても一切修正不要！ */
.card {
  background:    var(--color-bg-surface);
  color:         var(--color-text-primary);
  border:        1px solid var(--color-border-default);
}
4.5

アクセシビリティとコントラスト比

WCAG 2.1（Web Content Accessibility Guidelines）では、テキストの読みやすさを保証するためにコントラスト比の基準を定めています。

図を読み込み中...

▲ コントラスト比と合格基準の対応。3:1未満は使用禁止

WCAG 2.1 コントラスト比基準

基準レベル通常テキスト（〜17px）大きなテキスト（18pt以上/14pt太字以上）
AA（推奨最低基準） 4.5:1 以上 3:1 以上
AAA（理想基準） 7:1 以上 4.5:1 以上
不合格（使用禁止） 3:1 未満 3:1 未満

コントラストを意識したカラー設計

❌ NG — コントラスト不足
/* 薄い背景 + 薄いテキスト */
.badge-bad {
  /* #ede9fe 背景に */
  background: var(--purple-100);
  /* #c4b5fd テキスト */
  /* コントラスト比: 約2.3:1 → 不合格 */
  color: var(--purple-300);
}
✅ OK — AAA基準を満たす
/* 薄い背景 + 濃いテキスト */
.badge-good {
  /* #ede9fe 背景に */
  background: var(--purple-100);
  /* #5b21b6 テキスト */
  /* コントラスト比: 約7.5:1 → AAA合格 */
  color: var(--purple-800);
}
🔍
確認ツール： WebAIM Contrast Checker や Who Can Use でリアルタイムに確認できます。 Chrome DevToolsの「Inspect」パネルにもコントラスト比が表示されます。
4.6

カラーシステム — ベストプラクティス

✅ セマンティックトークンはプリミティブを参照する

❌ NG — ハードコード
:root {
  /* 直接値を書くと変更時に
     全箇所を探す必要がある */
  --color-danger: #ef4444;
  --color-danger-subtle: #fef2f2;
}
✅ OK — プリミティブを参照
:root {
  /* プリミティブ（1箇所で管理） */
  --red-500: #ef4444;
  --red-50:  #fef2f2;
  /* セマンティックはプリミティブを参照 */
  --color-danger:        var(--red-500);
  --color-danger-subtle: var(--red-50);
}

✅ コンポーネントには必ずセマンティックカラーを使う

❌ NG — プリミティブを直接使う
.alert-error {
  /* 意味が不明確。テーマ変更に弱い */
  background: var(--red-50);
  color:      var(--red-900);
  border:     1px solid var(--red-200);
}
✅ OK — セマンティックを使う
.alert-error {
  /* 用途が明確。テーマ変更に強い */
  background: var(--color-feedback-danger-subtle);
  color:      var(--color-feedback-danger);

5.2

タイプスケールの設計

モジュラースケール（等比数列）を使って、視覚的に調和したサイズ体系を作ります。全サイズが一定の比率で増加するため、統一感が生まれます。

Major Third（1.25倍）スケールの計算例

計算式
/*
  比率: 1.25（Major Third）
  base = 1rem = 16px

  xs:   1rem ÷ 1.25² = 0.64rem  ≈ 10px  → 注釈・キャプション
  sm:   1rem ÷ 1.25  = 0.8rem   = 12.8px → ラベル・補足
  base: 1rem          = 1rem    = 16px   → 本文テキスト ★基準
  lg:   1rem × 1.25  = 1.25rem = 20px   → リード文
  xl:   1rem × 1.25² = 1.563rem= 25px   → h4 見出し
  2xl:  1rem × 1.25³ = 1.953rem= 31px   → h3 見出し
  3xl:  1rem × 1.25⁴ = 2.441rem≈ 39px  → h2 見出し
  4xl:  1rem × 1.25⁵ = 3.052rem≈ 49px  → h1 見出し
*/

レスポンシブタイポグラフィ

clamp() 関数を使うと、画面幅に応じてなめらかにフォントサイズが変化するフルイドタイポグラフィを実現できます。

図を読み込み中...

▲ フルイドタイポグラフィ：320px〜1280pxの範囲で最小値〜最大値の間を線形補間

clamp() の構文と使い方

📐
clamp(最小値, 推奨値, 最大値)
推奨値はビューポート幅に依存する計算式。画面が狭ければ最小値、広ければ最大値で自動的にクランプされます。
CSS
/* clamp(最小, ビューポート依存の計算値, 最大) */

/* h1: 320px画面では 1.75rem → 1280px画面では 3rem へなめらかに変化 */
h1 {
  font-size: clamp(1.75rem, 3vw + 1rem, 3rem);
}

h2 { font-size: clamp(1.375rem, 2vw + 1rem, 2.25rem); }
h3 { font-size: clamp(1.125rem, 1.5vw + 0.75rem, 1.5rem); }

/* 本文は最小・最大を小さな範囲に固定 */
p {
  font-size: clamp(1rem, 1.25vw + 0.75rem, 1.125rem);
}

/* ── CSS変数との組み合わせ（推奨） ── */
:root {
  --font-size-h1:   clamp(1.75rem, 3vw + 1rem, 3rem);
  --font-size-h2:   clamp(1.375rem, 2vw + 1rem, 2.25rem);
  --font-size-h3:   clamp(1.125rem, 1.5vw + 0.75rem, 1.5rem);
  --font-size-body: clamp(1rem, 1.25vw + 0.5rem, 1.125rem);
}

h1 { font-size: var(--font-size-h1); }
h2 { font-size: var(--font-size-h2); }
p  { font-size: var(--font-size-body); }
🛠
計算ツール：clamp.font-size.app でビューポートサイズと最小・最大フォントサイズを入力すると、clamp() の値を自動計算してくれます。

スペーシング・サイジングシステム

6.1

スペーシングシステムの目的

余白・サイズを一定のルールに従って統一する仕組みです。「なんとなく16pxにした」ではなく、すべての余白が理由を持つ状態を目指します。

図を読み込み中...

▲ スペーシングシステムなし vs あり。マジックナンバーをトークンで置き換える

⚠️
マジックナンバーの問題：margin: 13px や padding: 17px のような根拠不明な数値が積み重なると、デザインの一貫性が失われ、変更のたびに全体を見直す必要が生じます。
6.2

ベースグリッドと数列

JavaScript — scroll-spy.js
document.addEventListener("DOMContentLoaded", () => {
  const observer = new IntersectionObserver((entries) => {
    const visibleSections = new Set();
    entries.forEach(entry => {
      if (entry.isIntersecting) visibleSections.add(entry.target);
    });
    if (visibleSections.size > 0) {
      const topSection = [...visibleSections].sort((a, b) => a.offsetTop - b.offsetTop)[0];
      updateScrollProgress(topSection.id);
    }
  }, { threshold: 0.1, rootMargin: "-10% 0px -80% 0px" });
  document.querySelectorAll(".sec").forEach(sec => observer.observe(sec));
});

ほとんどのデザインシステムは4px を基準単位として採用しています。デバイスのピクセル密度（1x / 2x / 3x）でキレイに割り切れるためです。

図を読み込み中...

▲ 4pxを基準に倍数で展開するスペーシングスケール（Material Design 等の業界標準）

なぜ 4px なのか

理由詳細
デバイス解像度との相性4px は 1x / 2x / 3x すべての画面密度で割り切れ、サブピクセルレンダリングの問題が起きない
視覚的な調和4の倍数（8, 16, 24, 32…）は黄金比に近く、自然に調和したレイアウトになる
業界標準Material Design・Tailwind CSS・Figma などの主要ツールが採用
