01

デザインシステムとは何か？

デザインシステムとは、一貫性のあるUIを効率よく構築するための「再利用可能なコンポーネント・ルール・ドキュメントの集合体」です。デザインと開発の両チームをつなぐ共通言語として機能します。

💡
わかりやすいたとえ
デザインシステムは「レゴブロックのセット」。ブロック（コンポーネント）の種類・色・接続ルールがあらかじめ決まっているため、誰が組み立てても一貫した作品になります。
全体構造（4層モデル）

図1.1 デザインシステムの4層構造

ある vs ない：何が変わるか
❌ デザインシステムなし
  • ボタンの色が #3498db / #2980b9 / rgb(52,152,219) とバラバラ
  • フォントサイズがページごとに異なる
  • 色を変えたい → 全ファイルを手動で修正
  • 新メンバーが何を使えばいいか迷う
✅ デザインシステムあり
  • --color-primary: #3498db を1箇所で定義
  • フォントスケールが統一されている
  • 色変更 → 変数1行を変えるだけで全体に反映
  • ドキュメントでルールが明確、迷いゼロ

02

CSS設計の基礎原則

CSSの「C」はCascade（カスケード）を意味します。複数のスタイルが同じ要素にぶつかったとき、どのスタイルが勝つかを決める仕組みを理解することが設計の出発点です。

カスケードの決定フロー

図2.1 スタイル競合時の優先度決定フロー

詳細度（Specificity）の計算

詳細度は (a, b, c, d) の4桁で表現します。数値が高い方が優先されます。

!important（⚠ 乱用禁止）
∞（最強）
style="" インライン
1,0,0,0
#id セレクタ
0,1,0,0
.class / [attr] / :hover
0,0,1,0
div / p / ::before タグ
0,0,0,1
* 全称セレクタ
0,0,0,0
CSS
/* ❌ 悪い例：詳細度が高すぎて上書き困難 */
#sidebar .navigation ul li a.active {
  color: blue; /* 詳細度: 0,1,2,3 → 非常に高い */
}
/* ✅ 良い例：フラットなクラスで詳細度を低く均一に */
.nav-link--active {
  color: blue; /* 詳細度: 0,0,1,0 → 低くて管理しやすい */
}
/* ✅ さらに良い：@layer で意図的に優先順位を制御 */
@layer components { .nav-link--active { color: blue; } }
@layer utilities  { .text-red { color: red; } /* utilities > components */ }
CSS設計の3大原則
🔁
DRY原則
Don't Repeat Yourself。同じスタイルを繰り返さず、CSS変数・ミックスインで共通化する
🎯
単一責任原則
1クラス＝1つの役割。.card__body・.card--featured のように役割を分担する
🔓
開放閉鎖原則
既存クラスを直接変更せず、.btn--danger のように新たなモディファイアを追加して拡張する

03

CSSカスタムプロパティ（変数）システム

CSS変数（CSSカスタムプロパティ）はスタイルの値に名前をつけて保存し、全体で使い回す仕組みです。1箇所変えるだけで全体に反映される「単一の真実の源」を実現します。

CSS変数の動作フロー

図3.1 CSS変数の定義から使用・変更の流れ

CSS変数 vs Sass変数：何が違う？
🔶 Sass変数 ($var)
  • コンパイル時に値が確定・固定される
  • ブラウザは最終CSSしか見えない
  • 実行時（JavaScriptから）変更不可
  • DevToolsで変数として表示されない
🔵 CSS変数 (--var)
  • ブラウザが実行時にリアルタイム処理
  • JavaScriptで動的に値を変更できる
  • DevToolsでリアルタイム編集・確認可能
  • 継承・スコープが使えてダークモード対応が簡単
完全な書き方ガイド
CSS
/* 命名規則：--[カテゴリ]-[サブカテゴリ]-[バリアント] */
:root {
  --color-primary-500: #3498db;
  --color-primary-600: #2980b9;
  --font-size-base: 1rem;
  --space-4: 1rem;
}
/* var() で参照 / フォールバック値も指定可 */
.button {
  background-color: var(--color-primary-500);
  font-size: var(--font-size-btn, var(--font-size-base, 1rem));
}
/* コンポーネントスコープで上書き */
.card { --card-padding: var(--space-6); padding: var(--card-padding); }
.card--compact { --card-padding: var(--space-3); }
ダークモード対応
CSS
:root { --bg-page: #ffffff; --text-base: #212529; }
/* ① OSの設定に連動（自動切替）*/
@media (prefers-color-scheme: dark) {
  :root { --bg-page: #0d1117; --text-base: #f0f6fc; }
}
/* ② data属性でJSから切替（手動切替）*/
[data-theme="dark"] { --bg-page: #0d1117; --text-base: #f0f6fc; }
/* コンポーネントは変更不要！変数を参照するだけ */
.card { background-color: var(--bg-page); color: var(--text-base); }
✅ 命名規則ベストプラクティス
  • プレフィックスでカテゴリを示す：--color- / --font- / --space- / --radius-
  • スケールは数値で表現：--space-4（16px）/ --color-blue-500
  • セマンティックな意味を持たせる：--color-primary / --text-muted
  • コンポーネント変数はスコープ内に：.btn { --btn-height: 2.5rem }

04

カラーシステム

プロのカラーシステムは3層構造で設計します。プリミティブ→セマンティック→コンポーネントの順に意味を付与することで、ブランドカラー変更時の影響範囲を最小化できます。

カラーシステムの3層構造
第1層：プリミティブカラー
純粋な色のパレット全体。意味を持たない原材料
blue-500: #3498db
第2層：セマンティックカラー
役割・意味を持つ変数名で定義。プリミティブを参照する
--color-primary → blue-500
第3層：コンポーネントカラー
特定UIに特化した変数。セマンティックカラーを参照する
--btn-bg → --color-primary
HSLカラーモデルによるパレット設計

タイポグラフィシステム

Modular Scale（比率ベーススケール）でフォントサイズを体系化し、フォントファミリー・行間・字間を統一することで、一貫した文字組みを実現します。

Modular Scale（比率: 1.25 Major Third）
トークン名rem値px換算用途
--text-xs0.64rem≈10px注釈・ツールチップ
--text-sm0.8rem≈13pxキャプション・補足
--text-base1rem16px本文（基準値）
--text-lg1.25rem20pxリード文・強調
--text-2xl1.953rem≈31pxh3
--text-4xl3.052rem≈49pxh1
CSS
:root {
  --font-sans: 'Noto Sans JP', -apple-system, sans-serif;
  --font-mono: 'JetBrains Mono', Consolas, monospace;
  --text-base: 1rem; --text-lg: 1.25rem; --text-xl: 1.563rem;
  --text-2xl: 1.953rem; --text-3xl: 2.441rem; --text-4xl: 3.052rem;
  /* clamp() でレスポンシブ対応 */
  --text-h1: clamp(var(--text-2xl), 4vw, var(--text-4xl));
  --leading-relaxed: 1.625; --leading-tight: 1.25;
  --tracking-tight: -0.025em; --tracking-widest: 0.1em;
  --font-bold: 700; --font-semibold: 600;
}
.prose { max-width: 65ch; line-height: var(--leading-relaxed); }

06

スペーシング・サイジングシステム

4pxベースグリッドで余白を統一します。すべての値が4の倍数であることでデザインに規則性が生まれ、Figmaなどのデザインツールとの整合性も高まります。

スペーシングスケール完全実装
CSS
:root {
  /* 命名：--space-[数値]  数値 × 4px = 実際のサイズ */
  --space-1: 0.25rem;  /*  4px */  --space-2: 0.5rem;   /*  8px */
  --space-3: 0.75rem;  /* 12px */  --space-4: 1rem;     /* 16px ← 基準 */
  --space-6: 1.5rem;   /* 24px */  --space-8: 2rem;     /* 32px */
  --space-12: 3rem;    /* 48px */  --space-16: 4rem;    /* 64px */
  /* コンポーネントサイズ（WCAG推奨：最小44×44px）*/
  --size-btn-md: 2.5rem;  /* 40px */  --size-btn-lg: 3rem;  /* 48px */
  --size-input:  2.5rem;  /* 40px */
  /* ボーダー角丸 */
  --radius-sm: 0.25rem;  --radius-md: 0.5rem;
  --radius-lg: 0.75rem;  --radius-xl: 1rem;  --radius-full: 9999px;
  /* ボックスシャドウ */
  --shadow-sm: 0 1px 3px 0 rgb(0 0 0 / 0.1);
  --shadow-xl: 0 20px 25px -5px rgb(0 0 0 / 0.1);
}
場所推奨値例
コンポーネント内部 padding--space-2 〜 --space-4ボタンのパディング
コンポーネント間 gap--space-4 〜 --space-6カードグリッドの隙間
セクション間--space-12 〜 --space-20ページ内の大見出し間
ページ外側余白モバイル: --space-4 / PC: --space-6コンテナの padding-inline

07

グリッド・レイアウトシステム

CSS GridとFlexboxは「どちらが優れているか」ではなく、用途に応じて使い分けるものです。2次元（行＋列）はGrid、1次元（横か縦）はFlexboxが最適解です。

Grid vs Flexbox 使い分け

図7.1 レイアウト手法の選択フロー

グリッドシステム完全実装
CSS
.container { width: 100%; max-width: 1280px; margin-inline: auto; padding-inline: var(--space-4); }
/* 自動レスポンシブグリッド：最小280px、空きがあれば自動でカラムが増える */
.auto-grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(min(280px, 100%), 1fr));
  gap: var(--space-6);
}
/* 名前付きエリアによるページレイアウト */
.layout-sidebar {
  display: grid;
  grid-template-columns: 260px 1fr;
  grid-template-areas: "sidebar main";
  gap: var(--space-8);
}
/* Flexboxパターン集 */
.flex-center  { display: flex; align-items: center; justify-content: center; }
.flex-between { display: flex; align-items: center; justify-content: space-between; }
.cluster { display: flex; flex-wrap: wrap; gap: var(--space-3); }
/* コンテナクエリ（2023年〜）：親要素の幅でスタイルが変わる */
.card-container { container-type: inline-size; }
@container (min-width: 30rem) {
  .card-inner { display: flex; flex-direction: row; gap: var(--space-4); }
}
✅ レイアウト選択ベストプラクティス
  • ページ全体・カードグリッドなど2次元は CSS Grid を使う
  • ナビゲーション・ボタングループなど1次元は Flexbox を使う
  • auto-fill + minmax() でメディアクエリなしのレスポンシブを実現
  • コンポーネントの自律的レスポンシブには Container Query を活用

コンポーネント設計とBEM命名規則

BEM（Block Element Modifier）はCSSクラスの命名規則で、可読性・再利用性・保守性を大幅に向上させます。CSS変数と組み合わせることで、現代的で強力なコンポーネント設計が実現できます。

BEM命名規則の構造

図8.1 Block / Element / Modifier の関係

概念記法例意味
Block.block.card独立した意味を持つ最小単位
Element.block__element.card__titleブロックを構成する部品（__ 二重アンダースコア）
Modifier.block--modifier.card--featuredバリエーションや状態（-- 二重ハイフン）
ボタンコンポーネント完全実装（CSS変数 + BEM）
CSS
.btn {
  --btn-bg: transparent; --btn-color: var(--color-text-primary);
  --btn-height: 2.5rem;  --btn-padding-x: 1rem;
  display: inline-flex; align-items: center; justify-content: center;
  height: var(--btn-height); padding-inline: var(--btn-padding-x);
  font-size: var(--text-base); font-weight: 500; white-space: nowrap;
  background-color: var(--btn-bg); color: var(--btn-color);
  border-radius: var(--radius-md); cursor: pointer;
  transition: background-color 150ms ease, transform 100ms ease;
}
/* :focus-visible → キーボード操作時のみフォーカスリング */
.btn:focus-visible { outline: 2px solid var(--color-border-focus); outline-offset: 2px; }
.btn:active:not(:disabled) { transform: scale(0.97); }
.btn:disabled { opacity: 0.5; cursor: not-allowed; }
/* バリアント：変数を上書きするだけ！ */
.btn--primary { --btn-bg: var(--color-primary); --btn-color: #ffffff; }
.btn--danger  { --btn-bg: var(--color-danger);  --btn-color: #ffffff; }
.btn--lg { --btn-height: 3rem; --btn-padding-x: 1.5rem; }
.btn--block { width: 100%; }

09

レスポンシブデザインシステム

モバイルファーストで設計します。小さい画面を基点にして min-width で大画面へ段階的に拡張することで、パフォーマンスと保守性の両方が向上します。

モバイルファースト vs デスクトップファースト
✅ モバイルファースト（推奨）
  • スマホ向けスタイルをまず書く
  • min-width で大画面に拡張
  • コンテンツ優先思考（Progressive Enhancement）
❌ デスクトップファースト（非推奨）
  • デスクトップ向けを先に書く
  • max-width で縮小・上書きする
  • 上書きの連鎖で保守が難しくなる
レスポンシブ実装完全ガイド
CSS
/* モバイルファースト（min-width を使う）*/
@media (min-width: 48em) { .container { padding-inline: var(--space-6); } }
@media (min-width: 64em) { .container { padding-inline: var(--space-8); } }
/* clamp() でメディアクエリ不要のレスポンシブ */
:root {
  --text-h1-fluid:  clamp(1.5rem, 4vw + 1rem, 3rem);
  --section-space:  clamp(2rem, 8vw, 6rem);
}
/* auto-fill グリッド（最も簡潔な自動レスポンシブ）*/
.grid-auto {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(min(250px, 100%), 1fr));
  gap: var(--space-6);
}
/* コンテナクエリ */
.product-grid { container-type: inline-size; }
@container (min-width: 37.5rem) { .product-list { grid-template-columns: repeat(3, 1fr); } }

アクセシビリティ（a11y）設計

アクセシビリティは「障害者向けの配慮」ではなく、すべてのユーザーにとっての使いやすさです。WCAG 2.1の4原則「POUR」に基づき、キーボード操作・スクリーンリーダー・コントラストを考慮したCSSを書きます。

WCAG 2.1の4原則（POUR）

図10.1 WCAGの4原則と主な達成基準

アクセシブルCSS完全実装
CSS
html { font-size: 100%; } /* ✅ ユーザー設定（通常16px）に従う */
/* ⚠️ outline: none は絶対にしてはいけない！ */
/* :focus-visible → キーボード操作時のみリングを表示 */
:focus-visible { outline: 2px solid var(--color-border-focus); outline-offset: 2px; }
/* スキップリンク */
.skip-link {
  position: absolute; top: -100%; left: 1rem; z-index: 9999;
  padding: .5rem 1rem; background: var(--color-primary); color: #fff;
  border-radius: var(--radius-md); transition: top 200ms ease;
}
.skip-link:focus { top: 1rem; }
/* スクリーンリーダー専用テキスト */
.sr-only {
  position: absolute; width: 1px; height: 1px; padding: 0; margin: -1px;
  overflow: hidden; clip: rect(0,0,0,0); white-space: nowrap; border-width: 0;
}

パフォーマンス最適化

CSSはレンダリングブロッキングリソースです。Critical CSS・未使用CSS削除・content-visibilityの3つを押さえるだけで、Core Web Vitalsが劇的に改善します。

Core Web Vitals 目標値
指標✅ 良好⚠️ 要改善意味
LCP≤ 2.5秒≤ 4.0秒最大コンテンツの描画時間
INP≤ 200ms≤ 500msインタラクションの応答時間
CLS≤ 0.1≤ 0.25レイアウトのズレ量
Critical CSS + PurgeCSS
HTML — Critical CSSインライン化
<head>
  <!-- ファーストビュー用CSSをインライン化（14KB以下を目標）-->
  <style>
    *, *::before, *::after { box-sizing: border-box; }
    body { margin: 0; font-family: system-ui, sans-serif; }
    .header { /* ヘッダーのみ */ } .hero { /* ヒーローのみ */ }
  </style>
  <!-- 残りは非同期で読み込む（media=print → onloadで all に変更）-->
  <link rel="stylesheet" href="/css/main.css"
        media="print" onload="this.media='all'">
  <noscript><link rel="stylesheet" href="/css/main.css"></noscript>
</head>
JavaScript — postcss.config.js（PurgeCSS）
module.exports = {
  plugins: [
    process.env.NODE_ENV === 'production' &&
    require('@fullhuman/postcss-purgecss')({
      content: ['./src/**/*.{html,js,jsx,tsx,vue}'],
      safelist: { standard: ['active','open','loading'], greedy: [/^btn--/,/^card--/] },
    }),
    process.env.NODE_ENV === 'production' && require('cssnano')({ preset: 'default' }),
  ].filter(Boolean),
};
CSS — content-visibility
/* 画面外コンテンツの描画を遅延 → 長いリストが劇的に高速化 */
.article-list-item {
  content-visibility: auto;
  contain-intrinsic-size: 0 300px; /* 推定サイズ（スクロール位置崩れ防止）*/
}
/* will-change は慎重に：ホバー時だけ有効化する */
.card:hover { will-change: transform; } /* ✅ 正しい使い方 */
/* .card { will-change: transform; } ← ❌ 常時指定はメモリの無駄 */
