Ch. 1

デザインシステムとは何か

1.1 定義と目的

デザインシステムとは、プロダクト全体で一貫したUIを構築するための「単一の信頼できる情報源（Single Source of Truth）」 です。デザインの原則・再利用可能なコンポーネント・ガイドラインをひとつのシステムとして統合したものを指します。

💡

Single Source of Truth とは？

「情報の唯一の正しい出所」という概念です。色、フォント、スペースなどの値をひとつの場所で定義し、すべての画面・コンポーネントがそこを参照します。変更が必要になったときも1か所を修正するだけで全体に反映されます。

デザインシステムを構成する4つの柱を図で確認しましょう。

図1.1 — デザインシステムの全体構造

デザインシステムがないと、以下のような問題が発生します。

問題カテゴリ 具体的な症状 影響度
見た目のばらつきページAは青いボタン、ページBは緑のボタン高
コードの重複同じようなコンポーネントが複数箇所に散在高
開発速度の低下毎回ゼロからUIを実装する中
保守コストの増大色を変えるだけで数十ファイルを修正高
チーム間の認識ずれデザイナーとエンジニアで「プライマリカラー」が違う高
アクセシビリティ後退コントラスト比などが各自バラバラに設定される中

デザインシステムがあるとないとでは、チームの動き方が根本的に変わります。

1.3 デザインシステムの構成要素

デザインシステムは「原子設計（Atomic Design）」の考え方で整理されることが多いです。Brad Frost が提唱したこの手法は、UIを5段階の抽象度で分類します。

図1.3 — Atomic Design の5段階階層
📚

参考：Atomic Design by Brad Frost

出典: https://atomicdesign.bradfrost.com/ — 原子設計の概念を詳細に解説した書籍（ウェブでも無料公開されています）

デザインシステムの最も根底にある概念が「デザイントークン（Design Tokens）」です。色・スペース・タイポグラフィなどの「値」を変数として定義し、全コンポーネントから参照します。

1.5 デザインシステムの構築ステップ

ゼロからデザインシステムを構築する際の推奨フローを示します。一気に完成させようとせず、段階的に育てていくアプローチが成功の鍵です。

図1.5 — デザインシステム構築の7ステップフロー
1

既存UIの棚卸し

現在使用されているすべての色・フォント・スペース・コンポーネントをリストアップします。意外にも数十〜数百種類の値が散在していることが多いです。

2

デザイン原則の言語化

「シンプルさを大切にする」「常にアクセシブルであること」など、設計の意思決定を支える価値観を文書化します。

3

デザイントークンの設定

プリミティブ → セマンティックの2層構造でトークンを定義します（CSS カスタムプロパティ推奨）。

4

基本コンポーネントの作成

Button・Input・Label・Badge などの原子（Atom）レベルのコンポーネントを定義します。

5

複合コンポーネントの組み合わせ

原子を組み合わせた SearchBar・Card・Modal などの分子（Molecule）・有機体（Organism）を構築します。

6

ドキュメントの整備

Storybook などを活用してコンポーネントの使い方・バリアント・禁止事項を記録します。

7

継続的なメンテナンス

デザインシステムは「完成」しません。プロダクトの進化に合わせて継続的に更新・改善します。

1.6 ベストプラクティス

デザインシステムの設計・運用で陥りやすいミスと、その解決策を示します。

✅ BP1：トークンは階層化して定義する

直接ハードコードされた値を使うと変更に弱くなります。必ずプリミティブ → セマンティックの2層構造を使います。

❌ NG — ハードコード
.button {
  /* 直書き。ブランドカラー変更時に
     全ファイルを検索・置換する必要あり */
  background: #6C47FF;
  border-radius: 8px;
  font-size: 14px;
}
✅ OK — トークン経由
.button {
  /* トークン変数を参照。
     :root の値を変えれば全体に反映 */
  background: var(--color-primary);
  border-radius: var(--radius-md);
  font-size: var(--text-body-sm);
}

✅ BP2：コンポーネントは「単一責任の原則」で設計する

コンポーネント自身は見た目だけを担当し、配置（マージン・幅）は使う側が決めます。

❌ NG — レイアウトを持つコンポーネント
.button {
  background: var(--color-primary);
  /* ↓ コンポーネントが外部のレイアウトに干渉 */
  margin: 0 auto;
  width: 100%;
  display: block;
}
✅ OK — 見た目だけを担当
.button {
  /* コンポーネント固有の見た目のみ */
  display: inline-flex;
  align-items: center;
  gap: var(--space-component-xs);
  padding: var(--btn-padding-v) var(--btn-padding-h);
  background: var(--color-primary);
  border-radius: var(--radius-md);
  /* margin・width は使う側に任せる */
}

2.1 CSSカスケードと詳細度

CSSで最も重要な概念のひとつが「カスケード（Cascade）」です。複数のスタイルが同じ要素に適用された場合、どれが優先されるかを3つのルールで決定します。

図2.1 — CSSカスケードの優先度決定ルール

CSS 詳細度の計算例 — 数値を比べることで適用順が決まる 
/* 詳細度: (0,0,0,1) — タグ1個 */
p { color: black; }

/* 詳細度: (0,0,1,0) — クラス1個 → 上より勝つ */
.text { color: blue; }

/* 詳細度: (0,1,0,0) — ID1個 → さらに勝つ */
#content { color: green; }

/* 詳細度: (0,1,1,1) — ID+クラス+タグ → 最も強い */
p.text#content { color: red; }

/* =========================================
   複合セレクタの計算練習
   ========================================= */

/* (0,0,1,1) — クラス1 + タグ1 */
nav li { color: gray; }

/* (0,0,2,1) — クラス2 + タグ1 */
.nav .nav-item { color: blue; }  /* こちらが勝つ */

/* (0,0,1,2) — クラス1 + タグ2 */
ul li.active { color: red; }    /* (0,0,1,2) vs (0,0,2,1) → (0,0,2,1) が勝つ */

/* =========================================
   !important — 最終手段（基本的に使わない）
   ========================================= */

/* 詳細度がどれだけ高くても !important が勝つ */
#very-specific-selector.and-class { color: purple; }
.simple-class { color: orange !important; } /* これが勝つ */
⚠️

!important の多用は厳禁

!important は「詳細度の戦争」を引き起こし、後からスタイルを変更することが困難になります。!important を使いたくなったら、設計を見直すサインです。CSS設計手法（BEM等）を適切に使えば、ほぼ必要ありません。出典: MDN — 詳細度

CSS Cascade Layers（@layer）— 最新の解決策

CSS Layers を使うと、詳細度に依存せずスタイルの優先順位を明示的に制御できます（2023年以降、全主要ブラウザ対応）。

CSS @layer — レイヤーで優先度を明示管理 
/* レイヤーの優先順位を宣言（後のレイヤーが強い） */
@layer base, tokens, components, utilities;

@layer base {
  /* リセットCSS・デフォルトスタイル */
  * { box-sizing: border-box; }
  p { margin: 0; }
}

@layer tokens {
  /* デザイントークン */
  :root {
    --color-primary: #6C47FF;
  }
}

@layer components {
  /* コンポーネント（詳細度が高くてもbaseに勝てる） */
  .button {
    background: var(--color-primary);
  }
}

@layer utilities {
  /* ユーティリティクラス — 最強 */
  .bg-transparent { background: transparent !important; }
}

2.2 主要なCSS設計手法

CSS設計には複数のアプローチがあります。それぞれの特徴を理解し、プロジェクトに合ったものを選択しましょう。

図2.2 — 主要CSS設計手法の概要

🔷 BEM（Block Element Modifier）

最も広く普及しているCSS命名規則です。Block__Element--Modifier の形式でクラス名を構成します。

図2.3 — BEM の3要素と命名規則
HTML + CSS BEM — カードコンポーネントの完全な例 
<!-- Block: .card（独立したコンポーネント）
     Modifier: .card--featured（状態・バリアント）
     Element: .card__image .card__title などのBlock内要素 -->
<article class="card card--featured">
  <img     class="card__image" src="thumbnail.jpg" alt="記事のサムネイル">
  <div     class="card__body">
    <span  class="card__category">デザイン</span>
    <h2    class="card__title">デザインシステム入門</h2>
    <p     class="card__description">UIの一貫性を保つ方法を解説...</p>
    <div   class="card__footer">
      <a   class="card__link card__link--primary" href="#">続きを読む →</a>
      <span class="card__meta">5分で読める</span>
    </div>
  </div>
</article>

/* Block — 独立したコンポーネントの基本スタイル */
.card {
  background: var(--color-bg-surface);

2.3 CSS変数（カスタムプロパティ）

CSS変数（正式名称：CSSカスタムプロパティ）は、現代のCSS設計の核心です。JavaScriptからも操作でき、動的なテーマ切り替えが可能になります。

図2.5 — CSS変数のスコープと継承の仕組み
CSS CSS変数の基本 — 定義・使用・フォールバック・スコープ 
/* ===== 1. 定義（:root = グローバルスコープ） ===== */
:root {
  --color-primary: #6C47FF;
  --spacing-unit: 4px;
}

/* ===== 2. 使用 ===== */
.component {
  color: var(--color-primary);
  padding: calc(var(--spacing-unit) * 4); /* → 16px */
}

/* ===== 3. フォールバック値（変数が未定義の場合） ===== */
.component {
  /* 第2引数がフォールバック。ネストも可能。 */
  color: var(--color-primary, var(--color-accent, #6C47FF));
}

/* ===== 4. スコープ（コンポーネントレベルの変数） ===== */
.card {
  /* .card の中でのみ有効。外部に漏れない。 */
  --card-padding: 24px;
  --card-bg: var(--color-bg-surface);

  padding: var(--card-padding);
  background: var(--card-bg);
}

/* スコープ変数をコンポーネント内で上書き */
.card--compact {
  --card-padding: 12px; /* コンパクト版は狭くする */
}

/* ===== 5. calc() と組み合わせる ===== */
:root {
  --base-size: 16px;
  --scale-ratio: 1.25;
}

.text-sm   { font-size: calc(var(--base-size) / var(--scale-ratio)); }
.text-base { font-size: var(--base-size); }
.text-lg   { font-size: calc(var(--base-size) * var(--scale-ratio)); }
.text-xl   { font-size: calc(var(--base-size) * var(--scale-ratio) * var(--scale-ratio)); }

/* ===== 6. JavaScript との連携 ===== */
/* CSS変数はJSから動的に変更できる */

/* JS:
   // 読み取り
   const color = getComputedStyle(document.documentElement)
     .getPropertyValue('--color-primary');

   // 書き込み（全体に影響）
   document.documentElement.style
     .setProperty('--color-primary', '#ff6b35');

   // 要素スコープで書き込み
   element.style.setProperty('--card-padding', '32px');
*/

2.4 レイアウト設計の基礎

現代のCSSレイアウトは「Flexbox（1次元）」と「CSS Grid（2次元）」を組み合わせて設計します。

図2.6 — Flexbox vs CSS Grid の使い分け

🔷 Flexbox — 1次元レイアウト

ナビゲーション・ツールバー・カードのアイテム整列など、1方向（行または列）のレイアウトに最適です。

CSS Flexbox の主要プロパティと典型的パターン 
/* ============================================
   Flexbox コンテナプロパティ
   ============================================ */
.flex-container {
  display: flex;

  /* 主軸方向（アイテムの並び方向） */
  flex-direction: row;          /* 横並び（デフォルト） */
  /* flex-direction: column; */  /* 縦並び */

  /* 主軸方向の揃え */
  justify-content: flex-start;   /* 左揃え */
  /* justify-content: center; */   /* 中央揃え */
  /* justify-content: flex-end; */ /* 右揃え */
  /* justify-content: space-between; */ /* 両端揃え、均等 */
  /* justify-content: space-around; */  /* 均等スペース */

  /* 交差軸方向の揃え */
  align-items: stretch;    /* 引き伸ばし（デフォルト） */
  /* align-items: center; */  /* 交差軸中央 */
  /* align-items: flex-start; */

  /* 折り返し */
  flex-wrap: nowrap;    /* 折り返さない（デフォルト） */
  /* flex-wrap: wrap; */ /* 折り返す */

  /* アイテム間スペース */
  gap: 16px;            /* 均等 */
  /* gap: 16px 8px; */  /* 縦 横 */
}

/* ============================================
   Flexbox アイテムプロパティ
   ============================================ */
.flex-item {
  /* 伸縮比率: grow shrink basis */
  flex: 1;           /* 等幅で伸びる */
  /* flex: 0 0 200px; */ /* 固定幅200px */
  /* flex: 2; */         /* 他のアイテムの2倍の幅 */

  /* 個別の交差軸揃え上書き */
  align-self: center;
}

/* ============================================
   実践的なパターン集
   ============================================ */

/* パターン1: ナビゲーションバー */

  display: flex;
  justify-content: space-between; /* ロゴ ←→ メニュー */
  align-items: center;

  background: var(--bg-surface);

/* パターン2: 中央揃えのページ全体 */

🔷 CSS Grid — 2次元レイアウト

ページ全体の骨格・複雑なダッシュボードなど、行と列の両方向を同時に制御したい場合に使います。

CSS CSS Grid — 主要プロパティと実践的なレイアウトパターン 
/* ============================================
   CSS Grid の基本
   ============================================ */
.grid-container {
  display: grid;

  /* カラム定義 */
  grid-template-columns: 200px 1fr 1fr;     /* 固定幅 + 可変幅2列 */
  grid-template-columns: repeat(3, 1fr);     /* 等幅3列 */
  grid-template-columns: repeat(12, 1fr);    /* 12カラムグリッド */

  /* アイテム間のスペース */
  gap: 24px;           /* 縦横同じ */
  /* gap: 32px 16px; */ /* 縦 横 */

   パターン1: レスポンシブカードグリッド（auto-fill）

あらゆる画面サイズで最適なUIを提供するための設計手法です。モバイルファースト（小さい画面から設計を始める）が現在の標準アプローチです。

図2.7 — モバイルファーストのレスポンシブ設計フロー
CSS モバイルファースト — 推奨の実装パターン 
/* =============================================
   ブレークポイント定義（コメントで管理）
   CSS変数はmedia query内では使えないため注意
   /* --bp-sm: 640px  */
   /* --bp-md: 768px  */
   /* --bp-lg: 1024px */
   /* --bp-xl: 1280px */
   ============================================= */

/* =============================================
   モバイル（デフォルト・min-width なし）
   320px 〜 767px をカバー
   ============================================= */
.container {
  padding: var(--space-component-md);

  gap: var(--space-component-md);

/* =============================================
   コンテナクエリ（Container Queries）— 最新手法
   親要素のサイズに応じてスタイルを変える
   2023年全主要ブラウザ対応
   ============================================= */
.card-container {
  container-type: inline-size;
  container-name: card;

   ビューポート幅に応じてフォントサイズが滑らかに変化
   ============================================= */
.heading-fluid {
  /* clamp(最小値, 理想値, 最大値) */
  font-size: clamp(1.5rem, 4vw, 3rem);
  /* 最小24px、4vw（画面幅の4%）、最大48px */
}

.spacing-fluid {
  padding: clamp(16px, 3vw, 48px);
}

  --header-height: 60px;
}

.modal {
  /* 意図が明確。ヘッダー高さ変更時も1箇所のみ */
  top: var(--header-height);
  height: calc(100vh - var(--header-height));
}

✅ BP3：アクセシビリティを標準で組み込む

CSS アクセシビリティのCSSベストプラクティス（WCAG 2.1準拠） 
/* 1. フォーカスインジケーターを絶対に消さない
      視覚的なフォーカスはキーボードユーザーの命綱 */
:focus-visible {
  outline: 2px solid var(--color-primary);
  outline-offset: 3px;  /* 要素と少し離す */
  border-radius: 3px;   /* 角を丸くして見やすく */
}

/* outline: none は禁止。どうしても消す場合は代替スタイルを必ず提供 */
.custom-button:focus-visible {
  outline: none; /* ← これだけはダメ */
  box-shadow: 0 0 0 3px var(--color-primary); /* 代替フォーカスリング */
}

/* 2. コントラスト比を確保する（WCAG AA基準: 4.5:1以上）
      デザイントークンでコントラスト値を管理する */
:root {
  /* これらの組み合わせはコントラスト比チェック済み */
  --text-on-white:  #374151;  /* 4.6:1 ✓ */
  --text-on-dark:   #f1f5f9;  /* 13:1  ✓ */
  --text-muted:     #6b7280;  /* 4.6:1 ✓ */

  /* NG 例: #999 on #fff = 2.85:1 → 基準未満 */
}

/* 3. 動きを減らす設定を尊重する */
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}

/* 4. スクリーンリーダー専用テキスト（視覚的に隠すが読み上げはされる） */
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border: 0;
}

/* 5. 高コントラストモード対応 */
@media (forced-colors: active) {
  .button {
    border: 2px solid ButtonText; /* システムカラーを使用 */
  }
}

✅ BP4：論理プロパティで国際化対応

❌ NG — 方向固定（RTL対応不可）
.element {
  margin-left: 16px;
  padding-right: 8px;
  border-left: 2px solid;
  text-align: left;
}
/* アラビア語・ヘブライ語（右から左）
   の言語では崩れる */
✅ OK — 論理プロパティ（RTL自動対応）
.element {
  margin-inline-start: 16px;  /* LTR→左, RTL→右 */
  padding-inline-end: 8px;    /* LTR→右, RTL→左 */
  border-inline-start: 2px solid;
  text-align: start; /* LTR→左, RTL→右 */
}
/* html[dir="rtl"] を設定するだけで
   レイアウトが自動的に反転する */

✅ BP5：パフォーマンスを意識したCSSを書く

CSS CSS パフォーマンス最適化のベストプラクティス 
/* 1. アニメーションは transform / opacity のみを使う
      これらはGPUで処理され、レイアウトを再計算しない */

/* ❌ NG: レイアウトに影響するプロパティをアニメーション */
.element-bad {
  transition: width 0.3s, height 0.3s, top 0.3s;
  /* → 毎フレームレイアウト再計算が発生（重い） */
}

/* ✅ OK: transform / opacity のみ */
.element-good {
  transition: transform 0.3s, opacity 0.3s;
  /* → GPUで処理。60fps維持可能 */
}

.slide-in { transform: translateX(100%); opacity: 0; }
.slide-in.active { transform: translateX(0); opacity: 1; }

/* 2. will-change で事前にGPUレイヤーを作る
      多用するとメモリ使用量が増えるので必要箇所のみ */
.modal {
  will-change: transform; /* アニメーション開始前に設定 */
}
/* アニメーション終了後は削除 */
.modal.done { will-change: auto; }

/* 3. contain プロパティで再計算範囲を限定 */
.isolated-component {
  contain: layout style paint; /* このコンポーネント外に影響しない */
}

/* 4. content-visibility で画面外のレンダリングをスキップ */
.article-card {
  content-visibility: auto;
  contain-intrinsic-size: 0 300px; /* スキップ時の推定サイズ */
}
