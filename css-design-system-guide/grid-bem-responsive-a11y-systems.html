7.グリッド・レイアウトシステム

7.1 レイアウトシステムとは

レイアウトシステムとは、ページ・コンポーネント内の要素配置ルールを体系化したものです。一貫した空間リズムを生み出し、予測可能な構造を保証することで、チーム全体の設計判断のブレをなくします。

レイアウトは3つのスケールに分かれており、それぞれ適切なツールが異なります。

図 7.1 — レイアウトの3スケールとツールの対応関係
💡
重要な原則：CSS Grid と Flexbox は競合ではなく補完関係にあります。Grid でページ骨格を組み、Flexbox でコンポーネント内部を整列する — このネストした使い方が現代のベストプラクティスです。

7.2 CSS Flexbox の完全ガイド

Flexbox は 1次元（行または列の一方向）のレイアウトを扱います。コンテナ（親）とアイテム（子）の2役でプロパティが分かれているのが特徴です。

主軸と交差軸の概念

図 7.2 — 主軸（Main Axis）と交差軸（Cross Axis）

コンテナプロパティ（親要素）

CSSFlexコンテナの全プロパティ
.flex-container {
  display: flex;                   /* Flexboxを有効化 */
  flex-direction: row;             /* row | row-reverse | column | column-reverse */
  flex-wrap: nowrap;               /* nowrap | wrap | wrap-reverse */
  justify-content: flex-start;     /* 主軸方向の整列 */
  align-items: stretch;            /* 交差軸方向の整列（単一行） */
  align-content: stretch;          /* 複数行の交差軸整列（wrap時のみ有効） */
  gap: 16px;                       /* アイテム間のすき間（row-gap / column-gap も可） */
}

/* justify-content の全値 */
/*
  flex-start    → 左端（デフォルト）
  flex-end      → 右端
  center        → 中央
  space-between → 両端固定・均等間隔
  space-around  → 全要素に等しい余白（端は半分）
  space-evenly  → すべての間隔が完全に等しい
*/

/* align-items の全値 */
/*
  stretch    → 交差軸方向に引き伸ばす（デフォルト）
  flex-start → 上揃え  |  flex-end → 下揃え
  center     → 中央揃え  |  baseline → ベースライン揃え
*/

アイテムプロパティ（子要素）

CSSFlexアイテムの全プロパティ
.flex-item {
  flex-grow:   0;      /* 余白があるとき伸びる割合（0=伸びない） */
  flex-shrink: 1;      /* 余白が足りないとき縮む割合（1=縮む） */
  flex-basis:  auto;   /* 初期サイズ（auto=コンテンツサイズ基準） */

  /* よく使うショートハンド */
  flex: 1;      /* = 1 1 0%   → 等幅で伸縮する */
  flex: auto;   /* = 1 1 auto → コンテンツ基準で伸縮 */
  flex: none;   /* = 0 0 auto → 固定サイズ（縮まない・伸びない）*/

  align-self: auto;  /* コンテナの align-items を個別上書き */
  order: 0;          /* 表示順（小さいほど前に来る）*/
}

典型的な実装パターン4選

CSSFlexboxの頻出パターン集
/* ① ナビゲーションバー（ロゴ左・アクション右）*/
.navbar {
  display: flex;
  align-items: center;
  justify-content: space-between;
  padding: 0 24px;
  height: 56px;
}
.navbar__actions { display: flex; gap: 8px; margin-inline-start: auto; }

/* ② 完全中央揃え */
.centered {
  display: flex;
  justify-content: center;
  align-items: center;
  min-height: 100svh;  /* svh: ブラウザUIバーを除いた高さ */
}

/* ③ カードフッターを常に下部に固定 */
.card {
  display: flex;
  flex-direction: column;
}
.card__body   { flex: 1; }    /* 余白をすべて吸収 */
.card__footer { flex: none; } /* フッターは高さ固定 */

/* ④ アイコン + テキストのリストアイテム */
.list-item { display: flex; align-items: center; gap: 12px; }
.list-item__icon { flex: none; width: 20px; }
/* min-width:0 が必須 → text-overflow:ellipsis を有効にする */
.list-item__text { flex: 1; min-width: 0; }
⚠️
min-width: 0 の罠：Flexアイテムはデフォルトで min-width: auto（コンテンツ幅を最小値とする）になっているため、text-overflow: ellipsis が効かないことがあります。flex: 1; min-width: 0 をセットで書くのが正解です。

7.3 CSS Grid の完全ガイド

CSS Grid は 行（Row）と列（Column）を同時に制御できる2次元レイアウトシステムです。複雑なページ構造も直感的なコードで表現できます。

図 7.3 — CSS Grid の重要用語

コンテナプロパティ

CSSGridコンテナの全プロパティ
.grid {
  display: grid;

  /* === カラム定義 === */
  grid-template-columns: 200px 1fr 1fr;      /* 固定+均等2列 */
  grid-template-columns: repeat(3, 1fr);     /* 3等分 */
  grid-template-columns: repeat(12, 1fr);    /* 12カラムグリッド */

  /* auto-fill: コンテナを可能な限り列で埋める */
  grid-template-columns: repeat(auto-fill, minmax(250px, 1fr));
  /* auto-fit: アイテム数に合わせて列数を調整（空列を詰める）*/
  grid-template-columns: repeat(auto-fit, minmax(250px, 1fr));

  /* === 行定義 === */
  grid-template-rows: auto 1fr auto; /* ヘッダー可変/コンテンツ拡張/フッター可変 */

  /* === 名前付きエリア（視覚的なレイアウト定義）=== */
  grid-template-areas:
    "header  header  header"
    "sidebar main    main  "
    "footer  footer  footer";

  /* === ギャップ === */
  gap: 16px;         /* 行・列両方 */
  row-gap: 24px;     /* 行間のみ */
  column-gap: 16px;  /* 列間のみ */

  /* === セルの整列（全アイテム）=== */
  place-items: center; /* align-items + justify-items のショートハンド */
}

アイテムプロパティ

CSSGridアイテムの配置プロパティ
.grid-item {
  /* ライン番号で配置 */
  grid-column: 1 / 3;       /* 列ライン1から3まで（2列分）*/
  grid-column: 1 / span 2;  /* 列ライン1から2列分 */
  grid-column: 1 / -1;      /* 左端から右端まで（全幅）*/
  grid-row:    2 / 4;       /* 行ライン2から4まで（2行分）*/

  /* 名前付きエリアで配置 */
  grid-area: header;   /* grid-template-areas の名前と一致させる */
  grid-area: sidebar;
  grid-area: main;
  grid-area: footer;

  /* 個別のセル内整列 */
  justify-self: center;   /* 列方向（水平）*/
  align-self:   end;      /* 行方向（垂直）*/
  place-self: center end; /* ショートハンド */
}

7.4 レイアウトパターン集

業界でよく使われる汎用レイアウトパターンを体系的に整理します。これらはコンポーザブル（組み合わせ可能）なプリミティブとして再利用できます。

CSS7つの汎用レイアウトパターン
/* ① RAMパターン（Repeat + Auto-fit + Minmax）
   メディアクエリなしで自動レスポンシブになるグリッド */
.ram-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(280px, 100%), 1fr));
  gap: 24px;
}
/* min(280px, 100%): 親が280px未満でも列幅がはみ出さない */

/* ② スタック（縦並び・等間隔）*/
.stack { display: flex; flex-direction: column; gap: 16px; }

/* ③ クラスター（タグ・バッジの折り返し）*/
.cluster { display: flex; flex-wrap: wrap; gap: 8px; align-items: center; }

/* ④ インセット（コンテンツを中央に収める）*/
.inset {
  max-width: 1280px;
  margin-inline: auto;
  padding-inline: clamp(16px, 5vw, 48px); /* 流動的な左右パディング */
}

/* ⑤ サイドバー付きレイアウト */
.with-sidebar {
  display: grid;
  grid-template-columns: min-content 1fr; /* sidebar=コンテンツ幅, main=残り */
  gap: 24px;
}

/* ⑥ フルブリード（本文の一要素だけ全幅に広げる）*/
.content-grid {
  --pad: clamp(16px, 5vw, 48px);
  --content: 680px;
  --breakout: 920px;
  display: grid;
  grid-template-columns:
    [full-start] minmax(var(--pad), 1fr)
    [breakout-start]
      minmax(0, calc((var(--breakout) - var(--content)) / 2))
      [content-start]
        min(100% - (var(--pad) * 2), var(--content))
      [content-end]
      minmax(0, calc((var(--breakout) - var(--content)) / 2))
    [breakout-end]
    minmax(var(--pad), 1fr) [full-end];
}
.content-grid > *           { grid-column: content; }
.content-grid > .breakout   { grid-column: breakout; }
.content-grid > .full-width { grid-column: full-start / full-end; }

/* ⑦ 等高カードグリッド */
.card-grid { display: grid; grid-template-columns: repeat(3, 1fr); gap: 16px; }
@media (max-width: 768px) { .card-grid { grid-template-columns: repeat(2, 1fr); } }
@media (max-width: 480px) { .card-grid { grid-template-columns: 1fr; } }

7.5 Flexbox と Grid の使い分け

「どちらを使うか？」という迷いは、以下のフローチャートで解消できます。

図 7.5 — Flexbox vs CSS Grid 判断フローチャート
場面推奨理由
ナビゲーションバーFlexbox横1列・アイテムの整列が主目的
ボタン内のアイコン＋テキストFlexbox1方向の整列・中央揃え
タグ・バッジのリストFlexbox + wrapコンテンツ量に応じた自然な折り返し

7.6 ベストプラクティス

✅レイアウト設計のベストプラクティス
✓
marginよりgapでアイテム間隔を管理する
margin は最後の要素に余分なスペースが残るなど計算が複雑。Flexbox/Gridの gap を使うと精確で予測可能な間隔管理ができます。
✓
min()/clamp()でメディアクエリを最小化する
repeat(auto-fit, minmax(min(280px, 100%), 1fr)) のようにすると、メディアクエリなしでレスポンシブなグリッドが実現します。
✓
place-itemsのショートハンドを活用する
place-items: center は align-items + justify-items を一括指定。Grid・Flex 両方で使えます。
✓
コンポーネントは外側マージンを持たせない
再利用性を損なうため、コンポーネント自体に margin をつけません。親コンテナの gap で管理するのが正解です。
❌ NG — marginで間隔管理
/* 最後の要素に余分なスペースが出る */
.card { margin-bottom: 16px; }
.card:last-child {
  margin-bottom: 0; /* 例外対応が必要 */
}
✅ OK — gapで間隔管理
/* 親の gap で一括管理 */
.card-list {
  display: flex;
  flex-direction: column;
  gap: 16px; /* 例外対応不要 */
}

8.コンポーネント設計とBEM命名規則

8.1 コンポーネント設計の5原則

コンポーネントとは単一の機能・見た目を持つ再利用可能なUI部品です。優れたコンポーネントは以下の5原則を備えています。

図 8.1 — コンポーネント設計の5原則
💜
原則の優先順位：5原則のうち、単一責任が最も重要です。「このコンポーネントは何をするか？」を1文で説明できないなら、分割を検討しましょう。

8.2 BEM の完全ガイド

BEM（Block Element Modifier）はCSSクラス命名の方法論です。命名規則だけでスタイルのスコープ・構造・バリアントを表現できるのが強みです。

図 8.2 — BEMの3層構造（Block / Element / Modifier）

BEM の構文

CSSBEM命名規則の基本構文
/* Block: 独立したコンポーネント（それ自体が意味を持つ）*/
.block {}

/* Element: Blockの一部（__ で連結。Block なしでは存在できない）*/
.block__element {}

/* Modifier: Block/Elementのバリアント・状態（-- で連結）*/
.block--modifier {}
.block__element--modifier {}

/* 具体例 */
.card {}                    /* Block */
.card__title {}             /* Element */
.card__body {}              /* Element */
.card--featured {}          /* Block Modifier（強調バリアント）*/
.card__title--truncated {}  /* Element Modifier（省略表示）*/

実装例：カードコンポーネント

よくある BEM の間違いと正解

❌ NG — __ を2重にネスト
<!-- card__header__title は存在できない -->

  </header>

8.3 CSS Modules / Scoped CSS

React・Vue などのコンポーネントフレームワークでは、CSSクラス名を自動でユニーク化してスコープを閉じ込める仕組みがあります。

JSXReact + CSS Modules
// Card.module.css
// ビルド時に .card_xK2aP のようなユニーク名に自動変換される
// .card { border-radius: 12px; }
// .card__title { font-size: 1.125rem; }

import styles from './Card.module.css';

function Card({ title, featured }) {
  return (
    <article className={`${styles.card} ${featured ? styles['card--featured'] : ''}`}>
      <div className={styles['card__body']}>
        <h2 className={styles['card__title']}>{title}</h2>
      </div>
    </article>
  );
}
HTMLVue の Scoped CSS
<template>
  <article class="card" :class="{ 'card--featured': featured }">
    <h2 class="card__title">{{ title }}</h2>
  </article>
</template>

<style scoped>
/* data-v-XXXXXX 属性が自動付与されこのコンポーネントのみに適用 */
.card { border-radius: 12px; }
.card__title { font-size: 1.125rem; }
.card--featured { border-color: var(--color-action-primary); }
</style>

8.6 ベストプラクティス

✅コンポーネント設計のベストプラクティス
✓
コンポーネントのCSSは外側マージンを持たない

9.レスポンシブデザインシステム

9.1 レスポンシブ設計の考え方

レスポンシブデザインとはデバイスの画面サイズに関わらず、最適なUI/UXを提供する設計手法です。現代ではモバイルファーストアプローチが強く推奨されています。

図 9.1 — モバイルファースト vs デスクトップファーストの比較
✅
モバイルファーストが推奨される理由：モバイルで必要な最小限のCSSをまず定義し、画面が広くなるにつれて機能を追加する「Progressive Enhancement」の考え方と合致します。デスクトップファーストでは不要なCSSをモバイルでも読み込む無駄が生じます。

9.2 ブレークポイントシステム

ブレークポイントはデバイスのサイズではなく、コンテンツが崩れるポイントで設定するのが正解です。

CSS代表的なブレークポイントとメディアクエリの種類
/*
  推奨ブレークポイント（Tailwind CSS 準拠）
  sm:  640px  → スマートフォン横向き
  md:  768px  → タブレット縦向き
  lg: 1024px  → タブレット横向き・小型ラップトップ
  xl: 1280px  → デスクトップ

/* ===== モバイルファーストの記述順序 ===== */

/* 4. 1024px 以上 */

  .component { font-size: 1.5rem; padding: 32px; }
}

/* ===== 範囲指定（CSS Level 4 モダン構文）===== */

9.3 コンテナクエリ

コンテナクエリは2023年に全モダンブラウザが対応したゲームチェンジャーです。ビューポートではなく親コンテナのサイズに応じてスタイルを変えられます。

図 9.3 — メディアクエリ（従来）vs コンテナクエリ（新機能）
CSSコンテナクエリの実装パターン
/* ===== Step 1: 親要素をコンテナとして登録 ===== */
.card-wrapper {
  container-type: inline-size; /* 幅を参照するコンテナ */
  container-name: card;         /* 名前付きコンテナ */
}

/* ===== Step 2: コンテナクエリでスタイルを分岐 ===== */
/* コンテナが500px未満（デフォルト）→ 縦積みレイアウト */
.card { display: flex; flex-direction: column; }

/* コンテナが500px以上 → 横並びレイアウト */
@container card (min-width: 500px) {
  .card {
    display: grid;
    grid-template-columns: 200px 1fr;
  }
}

/* ===== 実践：サイドバーあり・なし両方に対応するカード ===== */
.article-grid   { container-type: inline-size; }
.sidebar-widget { container-type: inline-size; }

/* コンテナが狭い → 縦積み */
.article-card { flex-direction: column; }

/* コンテナが広い → 横並び */
@container (min-width: 480px) {
  .article-card { flex-direction: row; }
}

/* コンテナが十分広い → サムネイル固定幅 */
@container (min-width: 640px) {
  .article-card {
    display: grid;
    grid-template-columns: 240px 1fr;
  }
}

/* ===== コンテナ単位（cqi / cqb）===== */
.card__title {
  font-size: clamp(1rem, 4cqi, 1.5rem);
  /* cqi: コンテナのインラインサイズ（幅）に対する%
     cqb: コンテナのブロックサイズ（高さ）に対する% */
}
📱
コンテナクエリの最大の恩恵：同じコンポーネントをどんな文脈（サイドバー内・メインコンテンツ内・モーダル内）に置いても適切に表示できます。ビューポート幅に依存する従来のメディアクエリでは不可能でした。

9.4 流動的レイアウトの技術

min()/max()/clamp()を活用すると、メディアクエリを書かずに流動的なレイアウトが実現できます。

CSSmin() / max() / clamp() 完全ガイド
/* ===== min(): 2つの値の小さい方を採用 ===== */
.element {
  width: min(600px, 100%);
  /* 親の幅が600px未満なら100%（はみ出さない）
     600px以上なら600px固定 */
}

/* ===== max(): 2つの値の大きい方を採用 ===== */
.element {
  padding: max(16px, 5vw);
  /* 5vwが16pxを下回ったら16pxを保証
     画面が広くなると5vwに追従 */
}

/* ===== clamp(最小, 推奨, 最大): 範囲内に収める ===== */
.element {
  width: clamp(300px, 50%, 800px);
  /* 300px〜800pxの範囲で50%に追従 */
}

/* ===== 流体タイポグラフィ（最も重要なユースケース）===== */
.heading-xl {
  font-size: clamp(1.5rem, 4vw + 0.5rem, 3rem);
  /* 小画面: 1.5rem → 大画面: 3rem でなめらかに変化
     "4vw + 0.5rem" が推奨値（vwのみだと極端すぎる）*/
}

/* ===== 流体スペーシング ===== */
.section {
  padding-block: clamp(32px, 8vw, 96px);
  /* 小画面: 32px → 大画面: 96px でなめらかに変化 */
}

/* ===== メディアクエリなしのレスポンシブグリッド ===== */
.auto-grid {
  display: grid;
  /* min(280px, 100%): 親が280px未満でも列幅がはみ出さない */
  grid-template-columns: repeat(auto-fit, minmax(min(280px, 100%), 1fr));
  gap: 24px;
}

/* ===== 流体コンテナパディング ===== */
.container {
  max-width: 1280px;
  margin-inline: auto;
  padding-inline: clamp(16px, 5vw, 48px);
  /* モバイル16px → タブレット以降は画面幅の5%を確保 */
}

10.アクセシビリティ（a11y）設計

10.1 アクセシビリティとは何か

アクセシビリティ（a11y = accessibility の a と y の間に11文字）とはすべての人がウェブを利用できるよう設計することです。障害を持つユーザーだけでなく、状況的制限のあるすべてのユーザーが対象です。

図 10.1 — アクセシビリティが対象とするユーザー
💡
カーブカット効果（Curb Cut Effect）：歩道の縁石カット（車椅子用）が、ベビーカー・スーツケース・自転車を使う人全員に恩恵をもたらすように、アクセシビリティ対応はすべてのユーザーのUXを向上させます。アクセシビリティはコンプライアンスではなく、品質の問題です。

10.2 WCAG ガイドラインの構造

WCAG（Web Content Accessibility Guidelines）はW3Cが定める国際的なアクセシビリティ標準です。日本の公共機関ではAAレベルへの適合が求められます。

図 10.2 — WCAG 2.2 の4原則（POUR）と適合レベル
原則意味代表的な要件
Perceivable（知覚可能）情報を複数の手段で提供altテキスト・字幕・色だけに頼らない
Operable（操作可能）キーボードでも操作できるフォーカス可視化・スキップリンク
Understandable（理解可能）わかりやすいUIとエラーラベル・エラーメッセージ・予測可能な動作
Robust（堅牢）支援技術でも機能するセマンティックHTML・ARIAの正しい使用

10.3 セマンティックHTML

セマンティックHTMLはアクセシビリティの最も重要な基礎です。適切な要素を使うだけで、多くのアクセシビリティ要件を自動的に満たします。

図 10.3 — 非セマンティック vs セマンティックHTMLの恩恵

視覚障害・運動障害のあるユーザーの多くはキーボードのみでウェブを操作します。マウスなしで完全に動作するUI設計は必須要件です。

  </a>

JavaScriptフォーカストラップ（モーダル内にフォーカスを閉じ込める）
function trapFocus(modalElement) {
  const focusable = modalElement.querySelectorAll(
    'a[href], button:not([disabled]), textarea, input, select, [tabindex]:not([tabindex="-1"])'
  );
  const first = focusable[0];
  const last  = focusable[focusable.length - 1];

  modalElement.addEventListener('keydown', (e) => {
    if (e.key !== 'Tab') return;

    if (e.shiftKey) {
      // Shift+Tab: 最初の要素にいたら最後に飛ぶ
      if (document.activeElement === first) {
        last.focus();
        e.preventDefault();
      }
    } else {
      // Tab: 最後の要素にいたら最初に飛ぶ
      if (document.activeElement === last) {
        first.focus();
        e.preventDefault();
      }
    }
  });
}

10.7 ベストプラクティス

✅アクセシビリティのベストプラクティス
✓
画像には常に適切なaltテキストを設定する
情報を持つ画像は内容を説明するaltを、装飾的な画像は alt=""（空文字）を設定します。空altは「読み飛ばす」という明示的な指示です。
✓
フォームは <label> と <input> を必ず関連付ける
placeholderだけのラベルは入力時に消えてしまいます。<label for="id">による明示的な関連付けが必須です。
✓
テーブルは <th scope> と <caption> を使う
scope="col"（列ヘッダー）・scope="row"（行ヘッダー）でスクリーンリーダーがデータとヘッダーの関係を正確に読み上げられます。
✓
自動化テストで継続的にチェックする
axe-coreなどのツールをCI/CDに組み込み、アクセシビリティの回帰を防止します。
